# CLAUDE.md — правила работы над QORGAN

QORGAN — учебная система мониторинга и раннего предупреждения паводков на р. Есиль (Ишим), Северо-Казахстанская область. Хакатон 28–29.10.2026, команда из 2 человек; участник 1 — новичок и управляет проектом через Claude Code Desktop. Основную реализацию делает Claude Code.

## Перед работой прочитай
1. `docs/PROGRESS.md` — где мы сейчас.
2. `docs/TASKS.md` — текущий этап, критерии готовности.
3. `docs/REQUIREMENTS.md` — требования (официальное ТЗ приоритетнее наших решений).
4. `docs/ARCHITECTURE.md` и `docs/DECISIONS.md` — перед любыми структурными изменениями.

## Обязательные правила
1. Перед крупными изменениями изучай актуальную документацию.
2. Работай последовательно, небольшими проверяемыми этапами.
3. Не переписывай работающие компоненты без обоснования.
4. Не удаляй пользовательские файлы без разрешения.
5. После изменений запускай подходящие тесты (`npm test`, `npm run build`).
6. Не заявляй об успешной проверке, если она не выполнялась.
7. Не скрывай ошибки и ограничения.
8. Не подменяй работающие функции статическими макетами; никаких декоративных кнопок.
9. Не выдавай симулированные данные за реальные: бейдж «ДЕМО-ДАННЫЕ», пороги помечены как учебные.
10. Обновляй `docs/PROGRESS.md` после завершения этапа.
11. Используй Git: коммит после каждого этапа, тег `checkpoint-*` перед рискованным изменением.
12. Не выполняй `git push` без явного разрешения пользователя.
13. Не публикуй секреты: пароли только в `.env` (в `.gitignore`), в git — `.env.example`.
14. Не устанавливай ненужные зависимости; новую зависимость — с обоснованием в `docs/DECISIONS.md`.
15. Все итоговые отчёты — на русском языке, понятном новичку.
16. При критическом архитектурном вопросе — остановись и спроси пользователя.
17. Не переходи к следующему этапу (Phase) без разрешения пользователя.

## Технические инварианты
- Риск, прогноз и предупреждения считаются **только на сервере**, один раз за тик, в одной транзакции SQLite; UI ничего не пересчитывает.
- Все данные одного экрана — из одного снимка `runId + tick`.
- Симулятор детерминирован: `scenario + params + seed` ⇒ одинаковый результат. Никакого `Math.random()` — только seeded PRNG.
- Сервер отдаёт коды причин/статусов, тексты переводит фронтенд (kk/ru/en). Никаких строк интерфейса в коде без ключа i18n.
- Алгоритм риска — МНК + правила. Не называть его ИИ/ML.
- Параметры станций и порогов — в БД (seed), не захардкожены в UI.

## Команды (появятся в Phase 1)
| Команда | Что делает |
|---|---|
| `npm install` | установить зависимости |
| `npm run dev` | сервер :3000 + фронтенд :5173 |
| `npm test` | все автотесты |
| `npm run build` / `npm start` | сборка и демо-запуск на :3000 |
| `npm run db:reset` / `npm run db:backup` | сброс БД к демо-состоянию / резервная копия |
