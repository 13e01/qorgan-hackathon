# CLAUDE.md — правила работы над QORGAN

QORGAN — учебная система мониторинга и раннего предупреждения паводков на р. Есиль (Ишим), Северо-Казахстанская область. Хакатон Digital Urpaq 28–29.10.2026, команда из 2 человек; участник 1 — новичок и управляет проектом через Claude Code Desktop. Основную реализацию делает Claude Code.

## Перед работой прочитай
1. `docs/PROGRESS.md` — где мы сейчас.
2. `docs/TASKS.md` — текущий этап, критерии готовности.
3. `docs/REQUIREMENTS.md` и `docs/tz/TZ-TRANSCRIPT.md` — требования. **Официальное ТЗ приоритетнее наших решений**; при сомнении смотри фото `docs/tz/tz-*.jpg`.
4. `docs/ARCHITECTURE.md` и `docs/DECISIONS.md` — перед любыми структурными изменениями.

## Обязательные правила
1. Перед крупными изменениями изучай актуальную документацию.
2. Работай последовательно, небольшими проверяемыми этапами.
3. Не переписывай работающие компоненты без обоснования.
4. Не удаляй пользовательские файлы без разрешения.
5. После изменений запускай подходящие тесты (`npm test`, `npm run build`).
6. Не заявляй об успешной проверке, если она не выполнялась.
7. Не скрывай ошибки и ограничения.
8. Не подменяй работающие функции статическими макетами; никаких декоративных кнопок.
9. Не выдавай симулированные данные за реальные: бейдж «ДЕМО-ДАННЫЕ», пороги помечены как учебные.
10. Обновляй `docs/PROGRESS.md` после завершения этапа.
11. Используй Git: коммит после каждого этапа, тег `checkpoint-*` перед рискованным изменением.
12. Не выполняй `git push` без явного разрешения пользователя.
13. Не публикуй секреты: пароли только в `.env` (в `.gitignore`), в git — `.env.example`.
14. Не устанавливай ненужные зависимости; новую зависимость — с обоснованием в `docs/DECISIONS.md`.
15. Все итоговые отчёты — на русском языке, понятном новичку.
16. При критическом архитектурном вопросе — остановись и спроси пользователя.
17. Не переходи к следующему этапу (Phase) без разрешения пользователя.

## Технические инварианты
- Телеметрия попадает в систему **только через `POST /api/telemetry`** (встроенный симулятор и MQTT-адаптер вызывают этот маршрут через `app.inject` со своим токеном в памяти, в БД напрямую не пишут).
- Внешний датчик (MQTT): один источник данных на прогон — `EXTERNAL_SENSORS` (только устройства, у симулятора нет таймера) или встроенная симуляция (показания датчика → `SOURCE_CONFLICT`, не записываются). 1 показание = 1 час модели (`hourMs`). Брокер — отдельный процесс, только 127.0.0.1, без анонимного доступа. Протокол — `apps/server/src/mqtt/protocol.ts`, docs/PYTHON_SENSOR.md.
- Время: реальное — только из `now()` приложения (`AppOptions.now`), виртуальное — только из часов прогона (`sim_start + current_tick × 60 мин`). Не смешивать; новые ответы с данными содержат `context` (режим и оба времени).
- Симулятор: команды и тики — через очередь `SimulationRunner.serialize`; таймер один. Тесты — `ManualScheduler`/`TestClock` (`apps/server/test/sim-helpers.ts`), без реальных ожиданий.
- Запись измерения всегда содержит станцию, время измерения, параметр, значение, единицу (ТЗ §5.2).
- Риск, прогноз и предупреждения считаются **только на backend**, в той же транзакции, что и запись пакета; UI ничего не пересчитывает.
- Все данные одного экрана — из одного снимка `runId + tick`.
- Симулятор детерминирован: `scenario + params + seed` ⇒ одинаковый результат. Никакого `Math.random()` — только хеш-шум.
- Сервер отдаёт коды причин/статусов/ошибок, тексты переводит фронтенд (kk/ru/en). Никаких строк интерфейса без ключа i18n.
- Алгоритм риска — баллы по факторам + МНК-тренд. Не называть его ИИ/ML/научным прогнозом; бейдж «ДЕМО-ДАННЫЕ · учебная модель» всегда виден.
- Станции, параметры, пороги и коэффициенты — в БД (меняет админ), не захардкожены в UI.
- Интерфейс (`apps/web`): только данные сервера (REST + `/ws`), никаких вычислений риска и сгенерированных значений в браузере; все строки — через `t()` с ключами в `ru.ts`/`kk.ts`/`en.ts`; уровни показываются в метрах, «Нет данных» вместо нуля; время — `Asia/Almaty`.
- Каждый новый маршрут API проверяет роль по матрице ARCHITECTURE §10 и валидирует вход (zod).
- Предупреждения (genesis) создаются только в `processAlerts` внутри транзакции `ingest`; закрываются при окончании прогона (`closeRunAlerts`). Отметки оператора — только через `/api/alerts/:id/view|resolve` (событие с автором).
- Прогноз по реке (`packages/shared/src/outlook`) — чистая функция, категорию риска не меняет; данные «до asOf» — правило как в T2; тренд истока вниз не передаётся.
- Административные изменения пишутся в `audit_log` в той же транзакции; токены устройств — только хеш.
- Интерфейс T4.1: цвета — только токены `styles.css` (темы `data-theme`), графики/карта берут их через `usePalette`; все команды симулятора — через общий `CommandGate` (`store.simCommand`); «Демо за 2 минуты» (`lib/demo.ts`) — рассказ поверх настоящего прогона, без своих таймеров и расчётов, этап — только по данным снимка.

## Команды
| Команда | Что делает |
|---|---|
| `npm install` | установить зависимости |
| `npm run setup` | создать `.env` из `.env.example` (случайный секрет сессий, демо-учётки) |
| `npm run typecheck` | проверка типов TypeScript во всех пакетах |
| `npm run dev` | backend :3000 + интерфейс http://localhost:5173 (Ctrl+C останавливает оба) |
| `npm run build` / `npm start` | собрать интерфейс / запустить сервер, который отдаёт интерфейс и API на http://localhost:3000 |
| `npm run demo:wave` | консольная демонстрация волны на отдельной демо-базе (`-- RAPID_FLOOD 60`) |
| `npm test` | все автотесты (Python-датчик: `py -m unittest discover -s sensors/python`) |
| `npm run mqtt:broker` | локальный MQTT-брокер для Python-датчика |
| `npm run build` / `npm start` | сборка и демо-запуск на :3000 |
| `npm run db:reset` / `npm run db:backup` | сброс БД к демо-состоянию / резервная копия |
| `npm run db:fixture` | записать проверочный прогон TEST_FIXTURE (12 ч данных, не симулятор) |

Окружение: Windows 11, Node 24.22.1, npm 11.19.1, Git 2.56 (Git Bash). Docker и `gh` не установлены.

Код: TypeScript без сборки — backend запускается через `tsx`, пакеты импортируют `@qorgan/shared` прямо из `src`. БД — `node:sqlite` (`DatabaseSync`), миграции в `apps/server/src/db/migrations.ts` (только добавлять новые, старые не менять). Изменения в нескольких таблицах — через `transaction()`. Тесты сервера — `fastify.inject()` + БД `:memory:` (`apps/server/test/helpers.ts`).
