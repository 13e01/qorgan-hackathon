# QORGAN Sentinel — Telegram-бот

> Учебная демонстрация. Бот не является официальной системой оповещения. Настоящие сообщения в этой работе
> **не отправлялись** — все проверки сделаны на заглушке Bot API (тесты и `npm run telegram:mock`).

## 1. Что делает
- Пишет **привязанным** операторам, когда в QORGAN возникает новый высокий риск (предупреждение открыто сразу с HIGH) или риск повышается MEDIUM → HIGH.
- Сообщение собирается только из события QORGAN: станция и код, уровень (м), учебные пороги W/D, риск, модельное время измерения (UTC+5), причина (`DANGER_LEVEL` — «превышен учебный опасный порог», `FORECAST` — «ухудшение прогноза»), оценка ML этого же тика (если есть), источник данных (симуляция / внешний датчик MQTT), ссылка «Открыть QORGAN» (`PUBLIC_URL`), пометка «Учебная демонстрация».
- Команды: `/start [КОД]`, `/help`, `/status`, `/stations`, `/alerts`, `/subscribe`, `/unsubscribe` — по данным сервера (те же публичные данные, что видит гость на карте). Язык ответа — ru/kk/en по языку Telegram при привязке.

## 2. Настройка
1. В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
2. Вписать **только в `.env`** (он в `.gitignore`; `npm run setup` добавит пустые ключи):
   ```
   TELEGRAM_BOT_TOKEN=<токен>
   PUBLIC_URL=http://localhost:3000
   # необязательно — только эти чаты могут привязаться и получать сообщения:
   TELEGRAM_ALLOWED_CHAT_IDS=
   ```
3. Перезапустить сервер (`start-demo.bat` или `npm start`). В журнале: «Telegram-бот: включён».
4. Войти в QORGAN оператором → «Предупреждения» → «Telegram-уведомления» → «Получить код привязки» → отправить боту `/start КОД` (или нажать «Открыть бота с кодом»).
5. «Отправить проверочное сообщение» — проверить связь.

Без токена бот выключен: QORGAN запускается и работает как обычно, в журнале предупреждений — «не настроены».

## 3. Безопасность
- Сообщения получают только чаты, привязанные к **активному** пользователю QORGAN через одноразовый код (8 символов, 10 минут, в БД — SHA-256, после использования недействителен). Знать имя бота недостаточно: непривязанный чат получает только подсказку `/start`, `/help` и «чат не привязан».
- Дополнительно — список разрешённых чатов `TELEGRAM_ALLOWED_CHAT_IDS` (для показа жюри).
- Только личные чаты (группы игнорируются). Отключённый пользователь перестаёт получать сообщения.
- Токен — только из окружения; в URL запроса к Telegram, но не в журнале, не в БД и не в ответах API (тест проверяет). В журнал пишутся только коды ошибок (`HTTP_429`, `NETWORK` …). Идентификаторы чатов в интерфейсе — последние 4 цифры.
- Привязка, подписка и отвязка — в `audit_log`.

## 4. Защита от спама и надёжность
- **Transactional outbox:** запись в очередь — в той же транзакции, что и событие предупреждения; отправка — отдельно.
- **Нет повторов:** `dedup_key = alert:<id>:HIGH:<chat>` (UNIQUE) — одно сообщение о высоком риске на предупреждение и чат. Новое измерение при том же риске сообщения не создаёт.
- **«Остывание» станции:** если по станции в этом прогоне сообщение о HIGH уже было не раньше 6 часов модели назад (предупреждение «мигнуло»), новая запись — `SUPPRESSED` (видна в журнале). Настройка — `TELEGRAM_COOLDOWN_TICKS`.
- **Частота:** не чаще 1 сообщения в чат за 1,1 с, не больше 20 за проход раз в секунду.
- **Ошибки Telegram:** 429 → пауза всей очереди на `retry_after`, попытка не тратится; сеть/5xx/таймаут → повтор через 2, 4, 8 … 60 с, не больше 6 попыток, остальные сообщения прохода не пробуются; 400/404 → `FAILED`; 403 (бот заблокирован) → `FAILED` и подписка чата выключается; 401 (токен отозван) → состояние «ошибка».
- **Устаревание:** сообщение, не отправленное за 30 мин (например, не было интернета), помечается `EXPIRED` и не уходит — старое предупреждение не должно приходить как новое.
- Опрос `getUpdates` (long polling, 25 с) — без входящих соединений, работает за NAT; при ошибках — пауза 5 → 60 с.

## 5. Журнал отправок
«Предупреждения» → «Telegram-уведомления» → «Журнал отправок»: время (реальное), что отправлялось, чат, состояние (в очереди / отправлено / не отправлено + код / пропущено).

## 6. Тесты (`apps/server/test/sentinel-telegram.test.ts`, заглушка `fetch`)
Без токена · привязка, одноразовость и истечение кода · команды на данных сервера и язык · полный прогон RAPID_FLOOD: по одному сообщению на станцию, текст из события · отписка, отключённый пользователь, список разрешённых · 429/502/400/403 · сеть недоступна → ограничение попыток · EXPIRED · права на чужую привязку и аудит · тексты ru/kk/en.

## 7. Показ без интернета: заглушка Bot API
```bash
npm run telegram:mock
```
Затем запустить сервер с `TELEGRAM_BOT_TOKEN=mock-token` и `TELEGRAM_API_BASE=http://127.0.0.1:8081` (например, конфигурация `sentinel-check` в `.claude/launch.json`). Страница http://127.0.0.1:8081/ — «чат» учебного пользователя: видно сообщения бота, можно отправить `/start КОД`, `/status`. Сообщения никуда не уходят. Для настоящего бота уберите `TELEGRAM_API_BASE`.
