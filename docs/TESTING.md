# QORGAN — Стратегия тестирования

Критерии ТЗ §9, которые закрывают тесты: «прогнозирование — корректность демонстрации» (TC-R, TC-S), «надёжность — проверка данных, роли, обработка ошибок» (TC-T, TC-P).

## 1. Уровни проверок

| Уровень | Инструмент | Что проверяем | Когда |
|---|---|---|---|
| Модульные | Vitest | модуль риска, генерация сценариев, хеш-шум, правила предупреждений | после каждого изменения `packages/shared`, `apps/simulator` |
| Интеграционные | Vitest + `fastify.inject()` + SQLite `:memory:` | телеметрия, транзакция, роли, CRUD, дубли | после изменений сервера |
| Сборка | `npm run build` | типы, сборка фронтенда | перед каждым коммитом этапа |
| Ручные E2E | чек-лист §6 | пользовательские сценарии | после T4–T6, T9 и перед защитой |
| Авто-E2E (доп.) | Playwright (~150 МБ загрузки, по согласованию) | смоук | только при запасе времени |

`npm test` — всё; `npm test -w packages/shared` — только расчёты. Тесты не зависят от интернета и случайности.

## 3a. Интерфейс — TC-U (T4)

Автотесты (`apps/web/test`, Vitest, без браузера): словари kk/ru/en — одинаковые ключи и подстановки, тексты для всех 25 кодов причин, перевод см → м в причинах; форматирование (метры, «нет данных» ≠ 0, знак после округления, время UTC+5); доступность команд симулятора по 6 состояниям, для гостя и во время отправки; живые данные — игнор устаревших/повторных снимков, новый прогон, слияние истории с точками во время загрузки, окно 24 ч для гостя; последнее измерение vs уровень в оценке.
Сервер (`apps/server/test/frontend-api.test.ts`): `situation` в снимке и ответах (RAPID_FLOOD тик 30: QRG-01 — местная опасность, QRG-02 — MEDIUM от угрозы сверху при нормальном уровне); неподтверждённый скачок в снимке; раздача собранного интерфейса и JSON-404 для `/api`.

**T4.1** (`apps/web/test/ui-prefs.test.ts`, `demo.test.ts`): тема (по умолчанию «как в системе», сохранение, неверное значение, недоступное хранилище), боковая панель (сохранение), язык (порядок KZ/RU/EN, сохранение, все новые строки переведены), защита от двойного нажатия (`CommandGate`), человеческие статусы (угроза сверху при нормальном уровне ≠ подъём), этапы демо (только по подтверждённым данным, подъём — 3 часа подряд или выше порога, не откатываются, один этап за час), команды демо (один `start`, двойное нажатие, конфликт с активным прогоном, продолжить/остановить и начать, выход, повтор, восстановление после перезагрузки, ошибки сервера).
Сервер (`apps/server/test/guided-demo.test.ts`): тот же `DemoController` против настоящего приложения — кнопка → `POST /api/simulation/start` → симулятор T3 → `POST /api/telemetry` → SQLite → T2 → снимок `/ws` → этап демо; все 5 этапов по порядку, их станции подтверждены измерениями и оценками в БД; выход и повтор; конфликт с прогоном оператора; гостю — 401; после выхода нет таймеров.

Проверено вручную во встроенном браузере (T4): см. docs/PROGRESS.md, запись T4. Авто-E2E в браузере (Playwright) не добавлялись — требуют загрузки браузера (~150 МБ, EX-006).

## 4. Приём телеметрии — TC-T

| ID | Проверка |
|---|---|
| TC-T01 | Корректный пакет → сохранены все 5 полей ТЗ §5.2 + `received_at`; ответ `accepted = n` |
| TC-T02 | Неверный/отсутствующий токен → 401; запись для отключённой станции → `STATION_DISABLED` |
| TC-T03 | Неизвестный параметр или не из набора станции → отклонено `UNKNOWN_PARAM` |
| TC-T04 | Неверная единица → `REJECTED_UNIT`; значение вне диапазона, NaN, −999 → `REJECTED_RANGE`; запись в `device_log` |
| TC-T05 | Повтор того же пакета → `duplicates = n`, в БД нет дублей |
| TC-T06 | `measuredAt` позже модельного времени → отклонено; раньше последнего → сохранено с `quality = 'late'` |
| TC-T07 | Нет сообщений > 3 × tick_ms → STALE, > 10 × → OFFLINE; восстановление → ONLINE и `RECONNECTED` |
| TC-T08 | Ошибка внутри транзакции → ничего из пакета не сохранено, ответ 500, прогон встаёт на паузу (TC-S20) |
| TC-T09 | Устройство станции: принимается только своя станция, допустимые единица/диапазон/время; запоздавшее — `late`, источник `device`; неверный токен пишется в журнал не чаще раза в минуту |

## 7. Правила

- Нельзя писать «проверено», если проверка не запускалась; в отчёте — команда и результат.
- Падающий тест не удаляют и не ослабляют без объяснения пользователю.
- Ошибку, найденную вручную, сначала воспроизводят тестом (если это занимает ≤ 15 мин), потом исправляют.
