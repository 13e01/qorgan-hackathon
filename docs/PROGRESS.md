### 2026-10-29 — Исправлены маркеры станций на карте (смещение и исчезновение при масштабе)

- **Симптом.** На карте главной панели маркеры Сергеевки, Явленки, Петропавловска и Соколовки были смещены
  относительно координат и пропадали при изменении масштаба (реальный Chrome, запуск через `start-demo.bat`).
- **Причина 1 (была с первой версии Eclipse).** При каждом снимке сервера `StationMap` перезаписывал `className`
  маркера целиком и стирал классы, которые MapLibre ставит один раз при создании: `maplibregl-marker`
  (`position: absolute`) и `maplibregl-marker-anchor-*`. Маркер выпадал в обычный поток страницы: каждый следующий
  оказывался ниже предыдущего на высоту подписи, а сдвиг MapLibre прибавлялся к этому месту — отсюда смещение, а при
  масштабе маркеры уходили за край карты (`overflow: hidden`).
- **Причина 2 (появилась при разделении сборки Hydro Future).** В `Root.tsx` две динамические загрузки стояли в одном
  тернарном выражении, и сборщик подключил зависимости (в том числе файл стилей карты `maplibre-gl.css`) только к
  загрузке главной. Файл стилей карты собирался, но браузер его не загружал.
- **Исправлено.** `lib/flow.ts` — `markerClassName`: свои классы маркера заменяются, чужие (MapLibre) сохраняются;
  `StationMap.tsx` использует его. `Root.tsx` — каждая загрузка в своей функции. Координаты станций, backend,
  датчик, MQTT и расчёт риска не менялись.
- **Проверено.** Новые тесты: классы маркера (`eclipse.test.ts`), настоящая production-сборка (`build.test.ts`:
  каждый CSS подключён, стили маркеров входят в загрузку рабочей системы, главная карту не тянет) — на старом коде оба
  падают. `npm test` — 309 Node-тестов, typecheck, build, Python — 19. Отдельный стенд :3110: точка каждого маркера
  совпадает с проекцией координаты станции (ошибка 0 px) на начальном масштабе, после +1, +2, −1, −2, после
  «Показать все станции», сдвига, выбора станции, смены тёмной/светлой темы и изменения ширины окна; маркер скрыт только
  когда станция вне кадра. Снимки — `docs/screenshots/eclipse/08–10-map-markers-*.jpg`.


### 2026-10-29 — Исправлен «чёрный экран» после пересборки (production)

- **Симптом.** После `start-demo.bat` сайт на :3000 был чёрным; в консоли — «Failed to load module script… MIME type
  of "text/html"» для старого `index-DkIXzy3p.js`. Не помогали перезапуск через BAT и режим инкогнито.
- **Причина.** (1) Сервер читал `index.html` один раз при старте и после `npm run build` продолжал ссылаться на удалённые
  файлы JS. (2) Раздача статики знала только файлы, существовавшие при старте (`wildcard: false`). (3) Отсутствующий
  `/assets/*.js` получал HTML-страницу с кодом 200 — браузер отказывался выполнять её как модуль. (4) Порт 3000 занимал
  `npm run dev` (`tsx watch`) из этой же папки, запущенный в 04:46 — раньше всех сборок Hydro Future; `start-demo.bat`
  видел, что порт занят «каким-то QORGAN», и открывал его, а `stop-demo.bat` такие ручные запуски не останавливает.
- **Исправлено.** `apps/server/src/app.ts`, `errors.ts`: `index.html` читается при каждом запросе с `Cache-Control:
  no-cache`, файлы ищутся на диске при каждом запросе, путь с расширением без файла — 404 (JSON), а не страница.
  `start-demo.bat`, `start-qorgan.bat` (ASCII + CRLF): если порт занят QORGAN, который отдаёт не ту сборку, что лежит в
  `apps\web\dist` этой папки, — понятная ошибка и что сделать, вместо чёрного экрана. Бизнес-логика не менялась.
- **Проверено.** Регрессионный тест в `frontend-api.test.ts` (на старом коде падает, на новом проходит); `npm test` —
  306 Node-тестов, typecheck, build, Python — 19. Проверка BAT в настоящем `cmd.exe`. Полный `start-demo.bat` с нуля на
  копии проекта (порты 3110/1993, своя база): три окна, сервер отдаёт свою сборку, все 9 модулей — 200 и
  `application/javascript`; пересборка без перезапуска сервера — новая страница сразу, старый файл — 404; во встроенном
  браузере главная и все 8 разделов без ошибок консоли; `stop-demo.ps1` копии остановил все три окна.
