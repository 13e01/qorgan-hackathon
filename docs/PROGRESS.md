## Журнал

### 2026-10-28 — T4 Интерфейс
- Сделано: `apps/web` (React + Vite + MapLibre + Recharts): главная панель с картой СКО (подложка OpenFreeMap, река Есиль из OSM, схема распространения, маркеры-кнопки), карточками станций, графиком с прогнозом и управлением симуляцией; страницы «Станции», «Аналитика», «Симулятор» (сценарий, seed, скорость, все команды, ручные вмешательства, история прогонов); вход/выход; WebSocket с переподключением; три языка. Сервер: `describeSituation` в снимке и ответах о риске, раздача собранного интерфейса. `npm run dev` запускает всё.
- Проверено автоматически: `npm test` — 159 тестов (66 общий пакет, 73 сервер, 20 интерфейс); `npm run typecheck` — 0 ошибок; `npm run build` — сборка без ошибок.
- Проверено во встроенном браузере (режим разработки и собранная версия): загрузка 4 станций и подложки (230 объектов OSM, подписи городов); неверный пароль → понятная ошибка; вход оператора; доступность кнопок по состояниям; запуск RAPID_FLOOD — станции меняются по очереди; пауза (виртуальное время стоит); изменение скорости на ходу; ручной сдвиг уровня + шаг; перезагрузка страницы (вход, режим и история восстановились); два перезапуска backend (баннер, «Данные не обновляются», переподключение за ~3 с, «Пауза» с пояснением); раздельное отображение итогового риска, локального уровня и угрозы сверху (Явленка: СРЕДНИЙ при нормальном уровне); переключение kk/ru/en на всех страницах; ширины 1920, 1366, 375 px без горизонтальной прокрутки; собранная версия на одном порту без ошибок в консоли.
- Найдено и исправлено при проверке: backend занимал порт интерфейса из-за внешней `PORT`; не загружался фоновый поток карты; карта при загрузке центрировалась на QRG-01 (повторный эффект); ложное «подложка недоступна» при скрытой вкладке; шапка сжималась под баннер; при неподтверждённом скачке показывался уровень из оценки вместо измерения; режим «Симуляция идёт» при потере связи; «+0 см/ч»; русская подпись на английской карте.
- Не проверено: внешний вид при видимой панели браузера на всех шагах (панель была скрыта — часть снимков без отрисовки WebGL; карта проверялась принудительной отрисовкой и запросом объектов); работа в Chrome/Edge пользователя; запуск из CMD; казахский текст носителем языка.

### 2026-10-28 — T3 Симулятор паводковой волны
- Сделано: генератор волны и 3 сценария (`packages/shared/src/simulation`); исполнитель с очередью команд, одним таймером и виртуальными часами в БД (`apps/server/src/simulation`); приём телеметрии `POST /api/telemetry` с проверками и одной транзакцией «измерения → часы → риск T2 → сохранение оценок»; API симулятора, станций, истории измерений и оценок; WebSocket `/ws`; ручные вмешательства; миграция v2; режим данных `context.mode` во всех ответах о риске; `npm run demo:wave`.
- Проверено: `npm test` — 130 тестов (61 общий пакет, 69 сервер); `npm run typecheck` — 0 ошибок; живой сервер (реальный таймер): миграция v2 на рабочей БД, старт RAPID_FLOOD 100 мс/тик, повторный старт → 409, пауза (тик не меняется 2 с), авторизованный прогноз оператора, полный прогон 260 тиков — станции дошли до HIGH на тиках 20 → 73 → 125 → 143, стоп во время хода — после него записей нет, сброс — данные сохранены; `npm run demo:wave` — волна прошла все 4 станции по порядку.
- Найдено и исправлено: (1) риск «мигал» LOW ↔ MEDIUM на спокойной воде из-за слишком сильного имитированного колебания уровня — уменьшено до 1 см и ±1 см (ADR-019); (2) в GRADUAL_FLOOD при 180 см у QRG-04 возникал HIGH — амплитуда 170 см; (3) маршруты риска брали реальное время не из общего источника — исправлено; (4) журнал неверных токенов мог расти без ограничения — не чаще раза в минуту.
- Ограничения: предупреждения (T5) ещё не создаются; токены устройств выпускает админ — T6; состояние источников и сценарий сбоев — T8; фактор «волна сверху» частично дублирует уже пришедшую волну (ADR-019).
- Не проверено: запуск из CMD/PowerShell (проверялось в Git Bash); работа WebSocket в настоящем браузере (проверено через тестовое подключение `injectWS`).

### 2026-10-28 — T2 Модуль оценки риска
