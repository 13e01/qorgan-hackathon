# QORGAN ECLIPSE — визуальная система «Живая река»

Ветка `revolution/qorgan-eclipse` (от `main` @ `16b01d0`, QORGAN Genesis). Изменён **только интерфейс** (`apps/web`):
сервер, общий пакет, Python-датчик, MQTT, схема БД, API и WebSocket не трогались.

## 1. Концепция
Река Есиль — центральный образ продукта. Пользователь за несколько секунд должен понять: это система мониторинга
паводков Северо-Казахстанской области; на карте — станции на реке; у каждой есть оценка риска; угроза движется сверху
вниз по течению; демонстрацию можно запустить одной кнопкой.

Характер: спокойный, точный, просторный. Цвет — для смысла (риск), а не для украшения; яркое появляется только тогда,
когда сервер сообщает об опасности.

## 2. Принципы
1. **Карта — главный объект.** Главная панель: строка обстановки → крупная карта (≈ 55–75 % высоты экрана) → «Живая река» → график.
2. **Сначала ответ, потом подробности.** Заголовок отвечает «что сейчас» одной фразой («Высокая опасность: Петропавловск»),
   детали — ниже и в раскрывающихся блоках (как в T4.1).
3. **Движение объясняет изменение.** Анимации есть только у того, что меняется: новое измерение, смена этапа демо,
   идущая вниз угроза, перелёт камеры к станции. Рабочие панели не «живут» сами по себе.
4. **Честность данных.** Всё на экране — из снимка сервера. Схема распространения угрозы подписана как схема;
   зон затопления нет (нет геоданных рельефа); бейдж «Демо-данные · учебная модель» виден всегда.
5. **Цвет не единственный носитель смысла.** Риск всегда написан словом; «угроза приближается» — пунктирное кольцо;
   связь «угроза идёт» — бегущий пунктир со стрелкой и подписью.

## 5. Типографика
Один шрифт — **Inter Variable** (`@fontsource-variable/inter`, оси wght + opsz, кириллица с казахскими буквами
ә ғ қ ң ө ұ ү һ і). Файлы входят в сборку — работает без интернета; браузер скачивает только нужные наборы символов.
| Уровень | Размер | Вес / трекинг |
|---|---|---|
| Главный заголовок (hero, этап демо) | `clamp(28px … 46px)` | 720, −0,038em |
| Заголовок страницы | `clamp(22px … 30px)` | 700, −0,03em |
| Ключевое значение (уровень, счётчик) | `clamp(30px … 42px)`, табличные цифры | 700 |
| Заголовок блока | 16,5 px | 650 |
| Основной текст | 14,5–16 px | 400–500 |
| Вторичная подпись / техническая | 12–13 px (не меньше 12 px) | 500–600 |

Цифры — табличные (`tabular-nums`), без декоративных шрифтов; заглавные только в логотипе.

## 6. Движение (motion)
| Что | Как | Зачем |
|---|---|---|
| Появление экрана | `reveal`: сдвиг 10 px + прозрачность, шаг 70 мс (`--i`) | порядок чтения: обстановка → карта |
| Смена этапа демо | заголовок и текст этапа появляются заново (`key`), не чаще раза за час модели | видно, что этап сменился |
| Новое измерение | число уровня плавно переходит к новому значению (`useTween`, 0,42 с); точка «данные идут» вспыхивает | видно, что данные живые, без мигания |
| Угроза вниз по течению | бегущий пунктир на карте (MapLibre `line-dasharray`, ~12 кадров/с) и в схеме реки | направление движения угрозы |
| Высокий риск на карте | медленная «волна» вокруг точки (2,4 с) | сигнал тревоги по данным сервера |
| Выбор станции | `flyTo` 1,1 с | где находится выбранная станция |
| Диалоги / уведомления | короткое появление 0,42 с | откуда взялось окно |

`prefers-reduced-motion: reduce` — все анимации и переходы отключаются, камера перемещается мгновенно,
бегущие линии стоят (смысл передают подпись и форма линии). Бегущий пунктир карты включается, только пока есть
связь «угроза идёт», — в спокойном состоянии таймеров анимации нет.

## 7. Архитектура интерфейса
- `src/styles.css` — токены (общие, светлая, тёмная) и базовые компоненты T4.1 (не переписывались, перекрашены токенами).
- `src/eclipse.css` — слой Eclipse поверх базы: оболочка, поверхности, главная панель, карта, «Живая река», демо,
  предупреждения, заголовки страниц, движение, адаптивность. Цвета — только токены.
- `src/lib/flow.ts` — чистые функции представления: `riverFlow` (узлы и связи реки по снимку), `labelOnLeft`
  (сторона подписи маркера), `alertLifecycle` (шаги обработки). Покрыты тестами `test/eclipse.test.ts`.
- `src/components/RiverFlow.tsx` — «Живая река»; `motion.tsx` — `useTween`, `useFresh`, `useReducedMotion`.
- `StationMap.tsx` — новые маркеры, связи по состоянию, свечение реки, сворачиваемая легенда, `flyTo`.
- `Shell.tsx` — навигация по группам «Мониторинг / Данные / Управление» (маршруты и права прежние, `navItems(role)`).
- `ui.tsx` — `PageHeader` (один h1 на экран), новые иконки, оформление входа.

### «Живая река» — откуда берётся состояние связи
| Состояние | Условие (данные сервера) |
|---|---|
| спокойно | у станции ниже нет фактора «волна сверху» от этой станции |
| угроза идёт | `situation.upstream.stationCode` станции ниже = станция выше, местного подъёма ещё нет |
| подъём дошёл | то же, и станция ниже сама показывает рост или выше порога |
| «угроза приближается» | самая верхняя станция со связью «угроза идёт» |

Срок «опасный уровень через ≈ N ч» берётся из прогноза по реке (`/api/outlook`, только после входа).

## 8. Ключевые решения
- **Боковая навигация, а не верхняя:** 7 разделов с казахскими подписями не помещаются в одну строку на 1366 px;
  боковая панель с группами быстрее читается и сворачивается до иконок.
- **Без motion/react:** все анимации — CSS и один `requestAnimationFrame`-хук; новая библиотека не дала бы пользы.
- **Стекло — только поверх карты и для навигации/диалогов:** рабочие карточки остаются плотными ради читаемости.
- **Схема реки отдельно от карты:** на карте реальная геометрия, а схема показывает порядок станций и состояние связей
  крупно и без наложения подписей; на телефоне становится вертикальной.

## 9. Ограничения
- Зоны затопления не рисуются — для них нужны рельеф и гидравлическая модель, которых в системе нет.
- Линии между станциями — схема (прямые отрезки), не русло; на карте это подписано в легенде.
- Анимация связи показывает направление угрозы, а не скорость воды.
- Подложка карты (OpenFreeMap) требует интернета; без него — однотонный фон, река и станции остаются.
- В консоли разработки встречаются предупреждения Recharts о повторяющихся ключах делений оси — графики в Eclipse
  не менялись; на `main` не проверялось.
