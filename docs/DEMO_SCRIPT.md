# Сценарий живой демонстрации (5–6 минут)

Сценарий «Быстрый паводок» (RAPID_FLOOD, seed 42) детерминирован: события всегда в одни и те же моменты.
1 час симуляции = 0,5 с; весь прогон 260 ч ≈ 2 мин 10 с.

## Подготовка (за 10 минут до выступления)
1. Ноутбук на зарядке, режим «не беспокоить», яркость максимум.
2. В корне проекта:
   ```bash
   npm run db:reset
   ```
   ```bash
   npm run build
   ```
   ```bash
   npm start
   ```
3. Открыть http://localhost:3000 в Chrome/Edge, масштаб 100 %, полноэкранный режим (F11). Тема — светлая (лучше видно на проекторе), язык — по аудитории.
4. Войти как `operator` (пароль — `SEED_OPERATOR_PASSWORD` в `.env`). Во второй вкладке — та же страница для входа администратором (раздел «Администрирование»).
5. Держать открытыми запасные материалы: скриншоты из `docs/screenshots/` (если сделаны) и видео прогона.

## Внешний Python-датчик через MQTT — защита за 1–2 минуты

Все значения на экране создаёт программа-датчик на Python и передаёт по MQTT; заранее подставленных данных нет. Время — с интервалом 2 с между показаниями (1 показание = 1 час модели).

**Подготовка (за 5 минут до выступления, без технических знаний):**
1. Двойной щелчок `start-demo.bat`. Дождаться в его окне строки `READY` (первый раз — несколько минут, дальше ~10–60 с). Открылись окна **QORGAN-server**, **QORGAN-broker**, **QORGAN-sensor** и сайт.
2. На сайте войти оператором (логин и пароль — в `.env`: `SEED_OPERATOR_USERNAME`, `SEED_OPERATOR_PASSWORD`).
3. «Симулятор» → «Внешние датчики» → блок **«Подготовить чистое демо»**:
   - если там «Идёт прогон №…» — нажать «Остановить прогон №…» → «ОК» (старый прогон останется в истории);
   - если пункт про уровень датчика жёлтый — в окне QORGAN-sensor набрать **N** и Enter, подождать около минуты до галочки;
   - все пункты с галочками → **не нажимать «Начать» заранее**, это шаг 3 показа.
4. Окна расположить: сайт — слева/на весь экран, окно QORGAN-sensor — справа или поверх (чтобы набирать буквы).

| Шаг (время) | Что сделать | Что произойдёт | Что сказать |
|---|---|---|---|
| 1. Запуск (0:00) | Показать три окна и сайт | Окна сервера, брокера и датчика; в окне датчика строки «#… NORMAL 320,… см» | «Три отдельные программы: сервер QORGAN, брокер сообщений MQTT и датчик уровня воды на Python». |
| 2. Норма (0:10) | Сайт: «Симулятор» → «Внешние датчики» | «MQTT: на связи», датчик «на связи», уровень ≈ 3,20 м; в чек-листе все галочки | «Датчик передаёт показания каждые 2 секунды. Сейчас уровень в норме». |
| 3. Включение приёма (0:20) | **«Начать новый чистый прогон»** | «Источник данных: внешние датчики (MQTT)», «Прогон №N: принято / отклонено 1 / 0, 2 / 0…» — счётчик растёт | «Новый чистый прогон: с нуля измерения, предупреждения и счётчики. Старые данные не удалены, они в истории». |

| 7. Просмотр (1:00) | «Предупреждения» → у Петропавловска **«Просмотрено»** | Статус «Просмотрено» | «Дежурный подтвердил, что увидел». |
| 8. Обработка (1:10) | **«Обработать»** → комментарий «Дежурная служба оповещена» → сохранить | Статус «Обработано» | «Действие оператора с комментарием сохраняется в журнале». |

После выступления: `stop-demo.bat` (или закрыть три окна). Для следующего показа — снова шаг 3 подготовки.

Что не говорить: «MQTT потребовали организаторы», «это настоящий датчик», «ИИ предсказал». Говорить: «программный датчик, отдельный процесс, стандартный протокол датчиков MQTT; пороги и уровни учебные».

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Не грузится подложка карты (нет интернета) | Сказать: «подложка — внешний сервис; река, станции и все расчёты работают локально». Продолжать. |
| Кнопка демо неактивна / «Симуляция уже идёт» | Выбрать «Остановить его и начать демо» — старый прогон сохранится. |
| Страница «зависла», баннер «Нет связи» | Проверить окно с `npm start`; перезапустить `npm start` — интерфейс переподключится сам, прогон встанет на паузу (нажать «Продолжить»). |
| Забыт пароль | Посмотреть `SEED_*_PASSWORD` в `.env`. |
| Ошибка при запуске `npm start` | `npm run build` ещё раз; занят порт 3000 — закрыть другой запуск (`npm run dev`). |
| Датчик пишет «брокер отказал в подключении» | Выполнить `npm run setup` и перезапустить QORGAN (создаст устройство с паролем из .env), затем датчик. |
| Датчик пишет «ждём QORGAN» | QORGAN не запущен или не подключился к брокеру: посмотреть окно QORGAN-server; брокер (QORGAN-broker) должен быть запущен. Проще всего — ещё раз `start-demo.bat`: он запустит только недостающее. |
| Показания датчика не появляются на сайте | Не начат прогон («Подготовить чистое демо» → «Начать новый чистый прогон») или идёт встроенная симуляция. Причины отклонений видны под счётчиком датчика (например, «приём датчиков не включён: 5») — это нормально до старта прогона. |
| Окно `start-*.bat` сразу закрывается / ошибки с обрывками русских слов | Это была старая версия BAT-файлов (UTF-8 + LF). Текущие — только латиница и CRLF. Запускать из папки проекта двойным щелчком. |
| «The sensor is ALREADY RUNNING in another window» | Датчик уже открыт в другом окне — пользоваться им. Второй экземпляр специально не запускается. |
| Уровень датчика застрял высоко | В окне датчика **N** + Enter (вернётся к 3,20 м примерно за минуту) или закрыть окно датчика (Q + Enter) и запустить `start-sensor.bat` заново. |
| Всё сломалось | `stop-demo.bat`, затем `start-demo.bat`. Если не помогло — показать скриншоты/видео и `npm test` (254 автотеста + 19 на Python) — это доказательство, что логика работает. |

## Запасной короткий сценарий (2 минуты)
Демо → дождаться «Прогноз по реке» в панели → «Проверить на истории» после окончания → один экран «Предупреждения». Три мысли: автоматические предупреждения с журналом, запас времени по каждому пункту, честная самопроверка.
