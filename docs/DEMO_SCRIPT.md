# Сценарий живой демонстрации (5–6 минут)

Сценарий «Быстрый паводок» (RAPID_FLOOD, seed 42) детерминирован: события всегда в одни и те же моменты.
1 час симуляции = 0,5 с; весь прогон 260 ч ≈ 2 мин 10 с.

## Подготовка (за 10 минут до выступления)
1. Ноутбук на зарядке, режим «не беспокоить», яркость максимум.
2. В корне проекта:
   ```bash
   npm run db:reset
   ```
   ```bash
   npm run build
   ```
   ```bash
   npm start
   ```
3. Открыть http://localhost:3000 в Chrome/Edge, масштаб 100 %, полноэкранный режим (F11). Тема — светлая (лучше видно на проекторе), язык — по аудитории.
4. Войти как `operator` (пароль — `SEED_OPERATOR_PASSWORD` в `.env`). Во второй вкладке — та же страница для входа администратором (раздел «Администрирование»).
5. Держать открытыми запасные материалы: скриншоты из `docs/screenshots/` (если сделаны) и видео прогона.

## Внешний Python-датчик через MQTT (1–2 минуты)

Подготовка: открыты три окна — `start-qorgan.bat` (сайт на http://localhost:3000), `start-broker.bat` (строка «MQTT-брокер QORGAN работает»), окно для `start-sensor.bat`. Встроенная симуляция остановлена.

| Шаг | Что нажать | Что произойдёт | Что сказать |
|---|---|---|---|
| 1 | На сайте: «Симулятор» → «Внешние датчики» → **«Принимать данные от датчиков»** | «Источник данных сейчас: внешние датчики (MQTT)», «MQTT: на связи» | «Теперь данные даёт не встроенный симулятор, а отдельное устройство. Источник один — данные не смешиваются». |
| 2 | Двойной щелчок `start-sensor.bat` | В окне датчика: «подключено», «QORGAN принимает данные», строки «#1 NORMAL 320,4 см отправлено» | «Это отдельная программа на Python — как датчик на реке. Она сама меряет уровень и отправляет по MQTT, со своим паролем устройства». |
| 3 | Показать «Станции» (или главную) | Панель «Внешние датчики»: Python-датчик, на связи, последнее показание, время, «PYTHON SENSOR»; у Петропавловска — «внешний датчик (MQTT)» | «Показание прошло весь путь: брокер → сервер → проверка → база → оценка риска → сайт». |
| 4 | В окне датчика: **D** + Enter | Уровень растёт на ~18 см за показание | «Включаем опасный подъём на самом устройстве». |
| 5 | Смотреть на сайт ~30 с | Риск Петропавловска: Низкий → Средний → Высокий; всплывает «Новое предупреждение» | «Сервер сам пересчитал риск и создал предупреждение — сайт ничего не считает». |
| 6 | «Предупреждения» → открыть → «История» | Причина: «уровень … выше опасного порога», «рост … см/ч»; ниже по течению — «угроза сверху» для Соколовки | «Причина записана в журнале; угроза передаётся вниз по реке». |
| 7 | (по желанию) закрыть окно брокера на 10 с и открыть снова | Датчик: «связь потеряна… в буфере N», потом «отправляю накопленные» | «Связь пропала — датчик не теряет показания, а отправляет их, когда сервер снова на связи». |

Что не говорить: «MQTT потребовали организаторы», «это настоящий датчик». Говорить: «программный датчик, отдельный процесс, стандартный протокол датчиков MQTT».

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Не грузится подложка карты (нет интернета) | Сказать: «подложка — внешний сервис; река, станции и все расчёты работают локально». Продолжать. |
| Кнопка демо неактивна / «Симуляция уже идёт» | Выбрать «Остановить его и начать демо» — старый прогон сохранится. |
| Страница «зависла», баннер «Нет связи» | Проверить окно с `npm start`; перезапустить `npm start` — интерфейс переподключится сам, прогон встанет на паузу (нажать «Продолжить»). |
| Забыт пароль | Посмотреть `SEED_*_PASSWORD` в `.env`. |
| Ошибка при запуске `npm start` | `npm run build` ещё раз; занят порт 3000 — закрыть другой запуск (`npm run dev`). |
| Датчик пишет «брокер отказал в подключении» | Выполнить `npm run setup` и перезапустить QORGAN (создаст устройство с паролем из .env), затем датчик. |
| Датчик пишет «ждём QORGAN» | QORGAN не запущен или не подключился к брокеру: проверить окно `start-qorgan.bat`; брокер должен быть запущен. |
| Показания датчика не появляются на сайте | Не включён режим «Принимать данные от датчиков» или идёт встроенная симуляция (в панели — «идёт встроенная симуляция — не записано»). |
| Всё сломалось | Показать скриншоты/видео и `npm test` (252 автотеста + 13 на Python) — это доказательство, что логика работает. |

## Запасной короткий сценарий (2 минуты)
Демо → дождаться «Прогноз по реке» в панели → «Проверить на истории» после окончания → один экран «Предупреждения». Три мысли: автоматические предупреждения с журналом, запас времени по каждому пункту, честная самопроверка.
