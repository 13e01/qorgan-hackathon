## День 1 — 28.10 (цель: MVP)

### T0. Phase 0 — анализ и документация
- **Цель:** понятный проверяемый план. **Результат:** `CLAUDE.md`, `README.md`, `docs/*`.
- **Готово, когда:** документы согласованы, ТЗ сверено (⚠️ ждём фото), пользователь одобрил переход к Phase 1.
- **Трудоёмкость:** 1 ч. **Риск:** ТЗ противоречит концепции → правка документов 0,5 ч.

### T1. Каркас монорепозитория и база данных (≈1,5 ч)
- **Цель:** проект запускается одной командой. **Результат:** npm workspaces (`apps/server`, `apps/web`, `packages/shared`), TypeScript, Vitest, миграции SQLite (`node:sqlite`), seed 4 станций и 2 демо-пользователей, `/api/health`.
- **Зависимости:** T0, разрешение на установку зависимостей (список — DECISIONS ADR-002…005).
- **Готово, когда:** `npm install`, `npm run dev`, `npm test` проходят; `GET /api/health` → 200; `npm run db:reset` пересоздаёт БД.
- **Авто:** TC-D01…D03. **Вручную:** открыть http://localhost:3000/api/health.
- **Риски:** конфликт портов, политики PowerShell для npm-скриптов → использовать Git Bash / cmd.

### T2. Расчёт риска — `packages/shared/risk` (≈1,5 ч)
- **Цель:** проверенная математика до появления UI. **Результат:** чистая функция `assessRisk(window, thresholds, upstream?, params)` по ARCHITECTURE §8.
- **Зависимости:** T1.
- **Готово, когда:** все TC-R01…R14 проходят, покрытие модуля ≥ 95 %.
- **Авто:** `npm test -w packages/shared`. **Вручную:** не требуется.
- **Риски:** граничные случаи (деление на 0, n=2) → покрыты тестами.

### T3. Симулятор, тиковый конвейер, REST и WebSocket (≈2,5 ч)
- **Цель:** живые данные в БД. **Результат:** сценарии, модель волны, состояния IDLE/RUNNING/PAUSED/FINISHED, тик в одной транзакции (измерения → риск → предупреждения → снимок), REST `/api/simulation/*`, `/api/state`, история, WS `/ws`.
- **Зависимости:** T1, T2.
- **Готово, когда:** SC-SEVERE прокручивается до конца; повтор с тем же seed даёт идентичные ряды; перезапуск сервера → PAUSED на последнем тике.
- **Авто:** TC-S01…S07, TC-P01…P04. **Вручную:** интерфейса ещё нет — проверка через тесты и `GET /api/state` в браузере; полная ручная проверка в T4.
- **Риски:** наложение тиков, гонки при паузе → один цикл `setTimeout` после коммита.

### T4. Интерфейс: оболочка, карта, Dashboard, панель симуляции (≈2,5 ч)
- **Цель:** первый показ волны. **Результат:** тёмная тема, навигация, i18n-каркас (все строки через ключи с первого дня, ru полностью, kk/en — хотя бы основные экраны), карта MapLibre с рекой и 4 станциями (цвет = риск), карточки станций, статистика, график уровня выбранной станции, кнопки старт/пауза/шаг/сброс/скорость/сценарий.
- **Зависимости:** T3.
- **Готово, когда:** запуск SC-SEVERE в браузере → станции по очереди краснеют на карте; график и карточка показывают тот же уровень, что карта.
- **Авто:** TC-I01 (ключи переводов), сборка `npm run build` без ошибок. **Вручную:** TC-E01, TC-E02.
- **Риски:** нет интернета → офлайн GeoJSON; производительность Recharts — ограничить точки окном.

### T5. Предупреждения — backend и UI (≈1,5 ч)
- **Цель:** оператор видит и подтверждает тревоги. **Результат:** логика §9, лента на Dashboard, страница Alerts (фильтр по статусу, подтверждение, закрытие, история событий).
- **Зависимости:** T3, T4. Подтверждение до T7 доступно без входа (временно; закрывается ролью в T7).
- **Готово, когда:** за прогон SC-SEVERE на каждую станцию ровно одно предупреждение; подтверждение сохраняется после перезагрузки.
- **Авто:** TC-A01…A06. **Вручную:** TC-E04.

### ✅ MVP — контрольная точка вечера 28.10
Должно работать без оговорок: запуск сценария → волна идёт по 4 станциям на карте → графики и прогноз ETA → предупреждения создаются и подтверждаются → перезапуск не теряет данные → переключатель языка работает (ru полностью).
Коммит + локальный тег `checkpoint-mvp`. Короткая запись экрана (резерв на случай проблем на защите).

## День 2 — 29.10 (цель: полнота и надёжность)

> Правило: к **12:00 29.10** всё обязательное должно быть показуемым; после — только исправления и подготовка защиты. Если защита раньше — показываем MVP.

### T6. Stations и Analytics (≈2 ч)
- Список станций, страница станции (история, пороги, параметры), Analytics: график нескольких станций (видно сдвиг волны), риск по времени, блок «Почему такой риск» (причины, ETA с диапазоном, доверие), выбор прошлого прогона.
- **Авто:** TC-P02, TC-P03. **Вручную:** TC-E03, TC-E05. **Риск:** перегруз графиков — максимум 500 точек на серию.

### T7. Вход и администрирование (≈1,5–2 ч)
- Логин/выход, роли operator/admin, защита команд; Admin: пороги и параметры станций (валидация W<D), включение/выключение станции, пользователи (если требует ТЗ), журнал аудита, кнопка резервной копии.
- **Авто:** TC-P05…P07. **Вручную:** TC-E06. **Риск:** ТЗ потребует больше функций пользователей → +1 ч.

### T8. Локализация полностью и дизайн (≈1,5 ч)
- Все ключи kk/en, форматы чисел/дат, проверка 1366×768, анимации пульса для HIGH, пустые состояния и ошибки.
- **Авто:** TC-I01, TC-I02. **Вручную:** TC-E08 (носитель казахского читает все экраны).

### T9. Тесты, сборка, восстановление (≈1,5 ч)
- Прогон всех тестов, `npm run build && npm start`, `start-demo.bat`, проверка восстановления (db:reset, backup, перезапуск во время RUNNING), README с инструкцией запуска.
- **Готово, когда:** все автотесты зелёные, чек-лист TESTING §5 пройден вручную.

### T10. Подготовка защиты (≈1 ч)
- Репетиция по `docs/DEMO.md` дважды, распределение ролей, ответы на вопросы, запасная видеозапись, проверка ноутбука (зарядка, режим «не беспокоить», масштаб экрана 100–125 %).
