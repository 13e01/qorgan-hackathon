### MVP по ТЗ §7 → наш план
Адаптивное приложение с картой (T4) · API и БД с историей (T1, T3) · автоматический поток от симулятора (T3) · обычный и опасный сценарии (T3) · расчёт риска с обоснованием (T2) · график, индикатор риска, автозапись предупреждения (T4, T5) · простая админ-панель со станциями, настройками и доступом (T6). **Всё это — день 1.**

## 4. Толкования неоднозначных мест (можно изменить)

| ID | Место ТЗ | Наше толкование |
|---|---|---|
| INT-001 | §4 «гость видит … опубликованные предупреждения» | Все автоматические предупреждения публикуются сразу; гость видит активные, без права отметок. Отдельного шага «опубликовать» нет |
| INT-002 | §4 оператор «просматривает … историю, прогноз» | Гостю — текущие значения, категория, факторы и график за 24 ч; полная история и аналитика — после входа |
| INT-003 | §5.2 «привязывать к выбранному сценарию ЧС» | Поле станции `hazard_type` (сейчас только `flood`); сценарии симулятора — отдельная сущность |
| INT-004 | §5.6 «просмотренное/обработанное» | Два статуса оператора: VIEWED и RESOLVED |
| INT-005 | §5.7 «отключать станции» | DELETE = статус `disabled` (история сохраняется) |

## 6. Расхождения ТЗ с первоначальной концепцией (исправлено)

| № | Было в концепции | Что требует ТЗ | Решение |
|---|---|---|---|
| D-01 | Симулятор внутри сервера, пишет в БД напрямую | Телеметрия через backend API (§5.3, §6) | Отдельный процесс → `POST /api/telemetry` |
| D-02 | Измерение = только уровень воды | Запись: станция, время, параметр, значение, единица (§5.2) | Универсальная модель `parameter/value/unit` |
| D-03 | Риск по одному показателю | «На основе нескольких показателей и/или их изменения» (§5.4); для паводков — уровень, скорость, осадки, температура (§3) | 5 факторов с весами |
| D-04 | 4 фиксированные станции | Создание станций, тип, статус, набор показателей (§5.2, §5.7) | CRUD станций и параметров |
| D-05 | Пользователи — «если потребуется» | Управление пользователями, CRUD (§5.7) | Обязательно, T6 |
| D-06 | Экран ноутбука | Адаптивное приложение (§7), критерий «адаптивность» (§9) | Вёрстка до 375 px |
| D-07 | Горизонт прогноза не указан | Указывать горизонт (§5.4) | Прогноз «на 3 ч» |
| D-08 | В предупреждении не было типа ЧС | Время, станция, тип ЧС, уровень, причина (§5.6) | Поля `hazard_type`, `trigger` |
