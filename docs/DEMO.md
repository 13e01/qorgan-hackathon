# QORGAN — Сценарий демонстрации (≈7 минут)

> Критерии ТЗ §9: функциональность 25 · прогнозирование 20 · техническая реализация 20 · **презентация и демонстрация 15** · дизайн 10 · надёжность 10. Обязателен **воспроизводимый сценарий изменения риска**.
> Роли: **П1** — ведущий (слайды и рассказ), **П2** — оператор (ноутбук). Оба должны уметь всё и объяснить любую часть.

## Подготовка (за 15 минут)
1. `npm run db:reset` → `start-demo.bat` → http://localhost:3000, полноэкранный режим (F11), язык ru.
2. Вкладка 1 — без входа (гость); вкладка 2 — оператор; вкладка 3 — админ. Телефон с открытым сайтом (по Wi-Fi ноутбука) — для показа адаптивности.
3. Проверить: карта загрузилась, бейдж «ДЕМО-ДАННЫЕ» виден, уведомления ноутбука выключены, зарядка подключена.
4. Заранее прогнать SC-SEVERE с seed 42 один раз — для сравнения прогонов на шаге 4:10, затем «Сброс».
5. Запасной план: видеозапись прогона (`checkpoint-mvp`) на рабочем столе.

## Если что-то пошло не так
- Нет интернета → карта показывает офлайн-слой реки, продолжаем.
- Backend упал → `start-demo.bat`; прогон встанет на паузу на последнем тике → «Продолжить».
- Всё плохо → видеозапись + архитектура по слайдам.

## Вероятные вопросы жюри
- **Это реальные данные?** Нет: реальная география (OpenStreetMap), показания от симулятора, пороги учебные. На экране это написано.
- **Это ИИ/ML?** Нет. Базовый вариант из ТЗ: прозрачные правила с весами и тренд по линейной регрессии. Мы честно не называем это научным прогнозом.
- **Почему эти показатели?** Уровень и его скорость — прямой признак затопления; дождь и потепление весной дают талый сток. Всё это есть в ТЗ для паводков.
- **Какой горизонт прогноза?** 3 часа для уровня (с диапазоном) + оценка времени до опасного порога.
- **Как избегаете ложных тревог и дублей?** Фильтр выбросов, проверка данных на входе, одно активное предупреждение на станцию, снятие условия только после 3 спокойных измерений.
- **Что если датчик пропал?** Статус ONLINE/STALE/OFFLINE, данные помечаются как устаревшие, запись в журнале диагностики.
- **Можно подключить настоящий датчик?** Да, ESP32 может слать тот же `POST /api/telemetry` с токеном станции.
- **Как проверяли?** Автотесты расчётов, симулятора, API и ролей (`npm test`), ручной чек-лист.
- **Что сделали сами?** Концепция, регион и станции, сценарии, модель риска, проверка; код писали вместе с ИИ-ассистентом (это разрешено) и можем объяснить любой модуль.
