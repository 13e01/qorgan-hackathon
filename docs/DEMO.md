# QORGAN — Сценарий демонстрации (≈6 минут)

> Черновик: финализируется после сверки с ТЗ и критериями оценки. Роли: **П1** — ведущий (рассказывает), **П2** — оператор (управляет ноутбуком). Меняться ролями можно — оба должны уметь всё.

## Подготовка (за 15 минут)
1. `npm run db:reset` → `start-demo.bat` → открыть http://localhost:3000 в полноэкранном режиме (F11), язык — русский.
2. Войти как оператор (в отдельной вкладке — админ).
3. Проверить: карта загрузилась, бейдж «ДЕМО-ДАННЫЕ» виден, звук/уведомления ноутбука выключены, зарядка подключена.
4. Запасной план: видеозапись прогона (`checkpoint-mvp`) на рабочем столе.

Длительность прогона SC-SEVERE: ≈226 тиков (107 у истока + 119 тиков добегания до Соколовки) → при 500 мс ≈ 2 мин. Для показа можно ставить 250 мс.

## Если что-то пошло не так
- Нет интернета → карта показывает офлайн-слой реки; продолжаем.
- Сервер упал → `start-demo.bat`, симуляция встанет на паузу на последнем тике → «Продолжить».
- Всё плохо → видеозапись + объяснение архитектуры по `docs/ARCHITECTURE.md`.

## Вероятные вопросы жюри
- **Это реальные данные?** Нет. Реальная география (OSM), учебные уровни и пороги. Архитектура позволяет заменить симулятор источником реальных данных.
- **Это ИИ/машинное обучение?** Нет, прозрачный алгоритм: линейная регрессия по последним 6 часам + правила. Его можно проверить и объяснить; на тестах — точные числа.
- **Как избегаете ложных тревог?** Фильтр одиночных выбросов, гистерезис закрытия (3 тика LOW), одно предупреждение на станцию.
- **Что будет при перезапуске?** Каждый тик — одна транзакция; восстанавливаемся с последнего тика на паузе.
- **Как проверяли?** Автотесты расчётов, симулятора, API (покажем `npm test`), ручной чек-лист.
- **Что вы сделали сами?** Концепция, выбор региона и станций, сценарии, проверка, тестирование; код писали с ИИ-ассистентом — это разрешено, и каждый может объяснить любой модуль.
