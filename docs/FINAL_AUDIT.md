## 2. Найдено при самопроверке и исправлено

| Проблема | Как нашли | Исправление |
|---|---|---|
| Запись предупреждения исчезала из списка «Активные», пока оператор писал комментарий (условие снялось) — текст терялся; при 0 активных было 4 необработанных | браузер | вид «Требуют внимания» (не обработаны) по умолчанию; параметр API `unhandled=true`; тест |
| Строка «Прогноз по реке» была скрыта на главной во время демо — именно когда смотрит жюри | браузер | строка в панели демо с 3-го шага |
| После перезапуска backend интерфейс выглядел вышедшим из системы | браузер | повторная проверка сессии при переподключении |
| Первые 51 ч прогона нижние станции не получали прогноз (нет истории верхней станции) | пробный прогон через API | допущение «до наблюдений уровень = первое измерение» с явной пометкой `assumedHistory` в API и интерфейсе |
| Тренд истока (3 ч) незаметно удлинял каскад на 3 ч малонадёжной экстраполяции | юнит-тест | тренд вниз по течению не передаётся |
| Сценарий показа обещал «Петропавловск через 93 ч» в строке на главной, а строка показывает ближайшую угрозу (Явленка) | сверка с данными | сценарий и слайд исправлены |
| Цифра «на 40-м часе» в документах была снята на 39-м часе | повторный замер | исправлено: 93 ч (окно 91–97), факт 91 ч |

## 4. Что не удалось доказать или проверить

- **Точность прогноза по реке на реальной реке.** Демо-данные создаёт симулятор, устроенный похоже на модель; высокая точность на них — не доказательство. Калибровки на архивах Казгидромета нет.
- **Docker-образ и Caddy** не собирались и не запускались (Docker не установлен). WebSocket за обратным прокси не проверен.
- **Казахские тексты** не вычитаны носителем языка.
- **Ноутбук команды и проектор** — не проверялись.
- Названия станций приходят из БД на русском и не переводятся.
- Выбор координат станции кликом по карте не сделан (ввод числами).
- Сравнение двух прогонов (T7) и сценарий сбоев датчиков (T8) не делались.
- Ограничение попыток входа хранится в памяти процесса (сбрасывается при перезапуске).
