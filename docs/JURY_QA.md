# Ответы на вопросы жюри

Отвечать коротко: сначала суть (1–2 предложения), потом — доказательство на экране, если спросят подробнее.

**Почему ваш проект лучше обычного мониторинга?**
Обычный мониторинг показывает, что уже произошло на датчике. QORGAN ещё (1) сам создаёт предупреждения и ведёт журнал реакции оператора и (2) для каждого пункта ниже по течению считает, сколько часов осталось до опасного уровня, по данным постов выше. На демо-сценарии Петропавловск получил предупреждение за 100 часов, а тренд самой станции — за 15.

**Что здесь инновационного?**
Не сам прогноз, а связка: запас времени по каждому населённому пункту + диапазон + **проверка на истории**. Система сама считает, насколько она ошибалась и насколько лучше наивного прогноза «уровень не изменится». В студенческих прототипах обычно есть только порог и цвет.

**Почему виртуальные датчики?**
ТЗ разрешает симулятор наравне с устройствами (§5.2) и не требует покупать оборудование. Симулятор отправляет данные через тот же `POST /api/telemetry`, что и настоящее устройство; у каждой станции можно выпустить токен устройства — ESP32 подключится без изменения кода.

**Насколько точен прогноз?**
На демо-данных — ошибка на сутки вперёд от 0,6 до 7 см против 58–69 см у наивного прогноза. Но мы прямо говорим: **это не доказательство** для реальной реки, потому что симулятор устроен похоже на модель. Честный пример — Петропавловск: модель промахивается по пику на ~40 см, потому что не знает о местном притоке. Для реальной реки нужна калибровка на архивах Казгидромета.

**Почему нет настоящего ML?**
Для обучения и проверки нужна многолетняя история уровней по постам Есиля — у нас её нет. ML без данных была бы надписью, а не моделью. ТЗ прямо допускает базовый вариант: прозрачные правила, веса и тренд (§5.4). Наша модель объясняет каждое решение и проверяет себя — следующий шаг после появления данных может быть статистическим.

**Что будет при отключении интернета?**
Система работает локально: сервер, база, расчёты, предупреждения. Без интернета пропадает только подложка карты; река и станции рисуются из локального файла. ИИ-сервисы не используются.

**Как подключить реальные станции?**
Администратор создаёт станцию (координаты, показатели, пороги, станция выше по течению) и выпускает токен устройства. Устройство отправляет `POST /api/telemetry` с заголовком `X-Device-Token`: станция, время, параметр, значение, единица. Сервер проверяет диапазоны и единицы, неверное пишет в журнал диагностики.

**Как обеспечена безопасность?**
Пароли — хеш scrypt; сессия в httpOnly-cookie; роли проверяются на каждом маршруте сервера (гость 401, оператор в админке 403); все входные данные проверяются схемами; токены устройств хранятся только как хеш; не больше 10 неудачных входов с IP за 10 минут; в публичном режиме сервер не запустится с демо-паролями и работает только по HTTPS.

**Сколько стоит внедрение?**
Программы — открытые, без лицензий. Сервер — около $4–6 в месяц. Существующие посты подключаются без закупки; новый недорогой пост — по нашей оценке $100–250 без монтажа. Точную экономию назвать нельзя без пилота; исследования Всемирного банка оценивают выгоды систем раннего оповещения в 4–36 раз выше затрат.

**Зачем ваш продукт, если есть государственные системы?**
Мы не заменяем Казгидромет и систему оповещения. Казгидромет выпускает бюллетени с окнами дат; QORGAN — рабочее место дежурного района: посты в реальном времени, автоматические предупреждения с журналом и запас времени по своему пункту. Он может брать данные государственных постов как ещё один источник.

**Что сделали участники, а что Claude Code?**
Честно: основной код и документы написал Claude Code по нашим заданиям. Команда выбрала тему и регион, сверяла решения с ТЗ, проверяла интерфейс, принимала решения по функциям и готовит защиту. Мы можем объяснить, как работает каждая часть, и показать тесты. *(Команде: скорректируйте этот ответ под то, как вы реально работали.)*

**Какие ограничения вы признаёте?**
Станции виртуальные; пороги и задержки учебные (реальная волна на Есиле идёт 7–10 суток, у нас от Сергеевки до Петропавловска сжато до ~4 суток); модель не учитывает лёд, поймы и сбросы водохранилищ; зоны затопления не рисуем — нет рельефа; названия станций не переводятся; казахский перевод не вычитан носителем; Docker-образ не собирался на нашем ноутбуке; это не сертифицированная система и не для реального реагирования без проверки службами.

**Почему предупреждение не исчезает, когда вода спадает?**
Условие снимается (после трёх спокойных оценок подряд), но запись остаётся в журнале, пока оператор её не обработает: важно, чтобы ни одно событие не осталось без реакции.

**Откуда пороги?**
Учебные значения, заданы в базе для каждой станции; администратор меняет их в панели, изменение сразу влияет на оценку и записывается в аудит. Официальные отметки Казгидромета мы не выдумываем.
