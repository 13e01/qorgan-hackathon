# Развёртывание QORGAN

| Способ | Когда | Docker нужен? |
|---|---|---|
| **A. Локально, режим разработки** | работа над кодом | нет |
| **B. Локально, собранная версия** | показ на защите с ноутбука | нет |
| **C. Публично: VPS + Docker Compose + Caddy** | ссылка для жюри | да (на сервере) |

> **Что проверено, а что нет (28.10.2026).** A и B проверены на Windows 11. Для C на ноутбуке команды **нет Docker**, поэтому образ **не собирался и не запускался**. Проверено без Docker то, что делает контейнер: запуск сервера с теми же переменными окружения (`PUBLIC_DEPLOYMENT=true`, `HOST`, `DB_PATH`, `BACKUP_DIR`) — отказ запускаться с демо-паролями, `/api/health`, раздача интерфейса, cookie с флагом `Secure`. Caddy и WebSocket через прокси **не проверялись**. Публикация в интернет — только с разрешения команды.

## A. Режим разработки (Windows)
```bash
npm install
```
```bash
npm run setup
```
```bash
npm run dev
```
Открыть http://localhost:5173. Остановить — Ctrl+C.

## B. Собранная версия на ноутбуке (рекомендуется для защиты)
```bash
npm run build
```
```bash
npm start
```
Открыть http://localhost:3000 — интерфейс и API с одного адреса. Перед показом: `npm run db:reset` (чистая база), затем «Демо за 2 минуты».

## C. Публичное размещение

### Почему VPS + Compose + Caddy
- SQLite нужен **постоянный диск**: на бесплатном Render диска нет и сервис засыпает через 15 минут ([Render](https://render.com/docs/free)) — база потеряется.
- VPS за $4–6 в месяц ([DigitalOcean](https://www.digitalocean.com/pricing/droplets), [Hetzner](https://www.hetzner.com/cloud/cost-optimized/)) — самый простой вариант с постоянным диском.
- Caddy сам получает и продлевает сертификат Let's Encrypt ([Caddy](https://caddyserver.com/docs/automatic-https)) и проксирует WebSocket `/ws`.
- Альтернативы без своего сервера: Fly.io (машина 512 МБ ≈ $3,69 + том $0,15/ГБ) или Railway Hobby ($5) — Dockerfile подходит, но конфигурации для них не готовились.

### Шаги (выполняет человек — платные ресурсы и публикация только с разрешения)
1. Арендовать VPS (Ubuntu 24.04, 1 ГБ RAM достаточно), установить Docker и Docker Compose.
2. Направить A-запись домена на IP сервера; открыть порты 80 и 443.
3. Скопировать проект на сервер (`git clone` нужной ветки).
4. Создать файл секретов (в git не попадает):
   ```bash
   cp .env.production.example .env.production
   ```
   Заполнить `SESSION_SECRET` (≥ 32 случайных символов) и **уникальные** пароли `SEED_*_PASSWORD` (≥ 12 символов). С демо-паролями сервер не запустится.
5. Запустить:
   ```bash
   DOMAIN=qorgan.example.kz docker compose up -d --build
   ```
6. Проверить: `https://<домен>/api/health` → `{"status":"ok",…}`; открыть сайт, войти администратором.
7. Для жюри создать отдельного оператора в «Администрирование → Пользователи»; после защиты — отключить.

### Что настроено в конфигурации
| Требование | Как |
|---|---|
| Секреты не в git и не во frontend | `.env.production` в `.gitignore` и `.dockerignore`; в браузер уходят только данные API |
| Без демо-паролей | `PUBLIC_DEPLOYMENT=true` → сервер проверяет секрет и пароли и не запускается при нарушении (`publicDeploymentProblems`, тест `deployment.test.ts`) |
| HTTPS | Caddy; cookie сессии `HttpOnly; Secure; SameSite=Lax` |
| IP клиента за прокси | `trustProxy` (нужен для журнала и ограничения попыток входа) |
| Перебор паролей | не больше 10 неудачных входов с IP за 10 минут → 429 |
| Админ-функции защищены | все `/api/admin/*` — только роль admin (401/403) |
| База не теряется | том `qorgan-data:/data` (`DB_PATH=/data/qorgan.db`) переживает пересоздание контейнера |
| Healthcheck | `HEALTHCHECK` в Dockerfile (`/api/health`); Caddy стартует после здорового приложения |
| Логи | JSON-логи Fastify в stdout; ротация Docker 3 × 10 МБ; `docker compose logs -f qorgan` |
| Корректная остановка | `tsx` запускается напрямую, SIGTERM закрывает сервер и БД |
| Заголовки безопасности | HSTS, nosniff, X-Frame-Options, Referrer-Policy (Caddyfile) |

### Резервное копирование
- Кнопка «Резервная копия БД» в «Администрирование → Источники данных» — `VACUUM INTO /data/backups/qorgan-ГГГГММДД-ЧЧММСС.db` (согласованная копия на работающем сервере).
- Из командной строки сервера:
  ```bash
  docker compose exec qorgan ./node_modules/.bin/tsx apps/server/src/db/cli.ts backup
  ```
- Скопировать копии с сервера: `docker compose cp qorgan:/data/backups ./backups`.
- Ежедневное копирование — cron на сервере с командой выше (не настраивалось).

### Обновление
```bash
git pull
```
```bash
DOMAIN=qorgan.example.kz docker compose up -d --build
```
Миграции БД применяются при запуске автоматически и только добавляют данные.

## Известные ограничения
- Один процесс и одна SQLite: горизонтальное масштабирование не предусмотрено (для одного бассейна не нужно).
- Ограничение попыток входа хранится в памяти процесса и сбрасывается при перезапуске.
- Подложка карты грузится с OpenFreeMap; без интернета остаются река, станции и все данные.
