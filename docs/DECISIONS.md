# QORGAN — Архитектурные решения (ADR)

Формат: решение · почему · альтернативы · влияние на сроки. Статус «предварительно» = до сверки с ТЗ.

### ADR-001. Монорепозиторий на npm workspaces — предварительно
- **Решение:** `apps/server`, `apps/web`, `packages/shared` в одном репозитории, один `npm install`.
- **Почему:** общие типы и расчёт риска без копирования; одна команда запуска для новичка.
- **Альтернативы:** pnpm/turborepo — лишняя установка и сложность.
- **Сроки:** 0.

### ADR-002. Backend: Node.js 24 + TypeScript + Fastify + `@fastify/websocket` — предварительно
- **Почему:** один язык с фронтендом; Fastify быстрый, есть `inject()` для интеграционных тестов без сети; официальный плагин WebSocket.
- **Запуск TS:** `tsx` в разработке, `tsc` для сборки. Валидация — `zod`.
- **Альтернативы:** Express (нет встроенной схемы/inject), NestJS (слишком тяжёлый для 2 дней).

### ADR-003. База данных: SQLite через встроенный модуль `node:sqlite` — предварительно
- **Решение:** `DatabaseSync` из `node:sqlite` (встроен в Node 24). Проверено 2026-10-28: работает без флагов, SQLite 3.53.4.
- **Почему:** не нужна компиляция нативных модулей на Windows (главный риск `better-sqlite3`), один файл БД, лёгкий бэкап (`VACUUM INTO`).
- **Без ORM:** SQL-миграции в файлах + тонкий слой репозиториев — меньше магии, проще объяснить.
- **Запасной вариант:** `better-sqlite3` (почти тот же синхронный API) — замена ≈ 30 мин.

### ADR-004. Frontend: React 19 + TypeScript + Vite + MapLibre GL + Recharts + Tailwind CSS — предварительно
- **Состояние:** Zustand для живого снимка; история — обычный `fetch`.
- **UI-компоненты:** Tailwind + собственные простые компоненты; без тяжёлых UI-библиотек. Иконки — `lucide-react`.
- **Карта:** стиль OpenFreeMap `dark` (бесплатно, без ключа, проверен — HTTP 200) + встроенный GeoJSON реки из OSM как офлайн-запас. Атрибуция OSM обязательна.
- **Почему не Leaflet:** MapLibre лучше выглядит в тёмном векторном стиле и плавнее анимирует; сложность сопоставима.
- **Риск:** Recharts тормозит на тысячах точек → ограничиваем серии 500 точками.

### ADR-005. Локализация: i18next + react-i18next, сервер отдаёт только коды — предварительно
- **Почему:** один источник фраз, переключение без перезагрузки, тест на полноту ключей.

### ADR-006. Риск и прогноз считаются только на сервере, раз за тик, и сохраняются — принято
- **Почему:** гарантирует, что карта, графики, прогноз и предупреждения согласованы (REQ-007), и что историю риска можно показать и объяснить.
- **Альтернатива:** расчёт в браузере — разные вкладки могли бы показывать разное.

### ADR-007. Прозрачный алгоритм риска: МНК-наклон + правила, без ML — принято
- **Почему:** проверяем автотестами с точными числами, объясним жюри за 30 секунд, честно. Данных для обучения ML нет.
- **Учтено:** мало данных, нулевой рост, спад, превышенный порог, выбросы, неопределённость (ARCHITECTURE §8).

### ADR-008. Детерминированный симулятор с seed и дискретными тиками — принято
- **Почему:** воспроизводимость, тестируемость, «шаг» на защите. 1 тик = 1 час симуляции.
- **Задержка волны:** из реальных расстояний по руслу (OSM) и **учебной** скорости 3 км/ч.

### ADR-009. Один тик — одна транзакция SQLite — принято
- **Почему:** нет частично записанных тиков; уникальные ключи исключают дубли измерений и предупреждений; после сбоя восстанавливаемся с последнего целого тика.

### ADR-010. REST для команд, WebSocket только для рассылки снимков — принято
- **Почему:** команды получают понятные коды ошибок (409/403), WebSocket остаётся простым; при переподключении клиент просто получает новый снимок.

### ADR-011. Минимальная авторизация: 2 роли, cookie-сессия, scrypt — предварительно (зависит от ТЗ)
- **Почему:** админ-функции должны быть защищены, но OAuth/регистрация не дают баллов.

### ADR-012. Демо-запуск одним процессом на порту 3000 — принято
- **Почему:** меньше движущихся частей на защите; `start-demo.bat` для запуска двойным кликом.

### ADR-013. Docker и публичный деплой — отложено
- **Почему:** на Windows 11 Docker не установлен (проверено), установка тяжёлая. Делаем, только если требует ТЗ или останется время (EX-001, EX-002).
