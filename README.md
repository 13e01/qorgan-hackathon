# QORGAN

**Интеллектуальная платформа мониторинга и раннего предупреждения паводков** в Северо-Казахстанской области (р. Есиль / Ишим). Прототип для хакатона **Digital Urpaq**, 28–29 октября 2026.

> ⚠️ Учебный прототип. Все показания **демонстрационные** (от симулятора), станции виртуальные, пороги и коэффициенты учебные. Реальна только география (OpenStreetMap). Не является сертифицированной системой оповещения.

## Что умеет
- **Источник телеметрии:** встроенный симулятор передаёт уровень воды, осадки и температуру через REST API (`POST /api/telemetry`) с настраиваемой скоростью виртуального времени. Сценарии: обычный режим, постепенный и быстрый паводок; пауза, шаг, остановка, ручные вмешательства. Результат воспроизводим по seed.
- **Паводковая волна:** подъём у Сергеевки доходит по реке до Явленки, Петропавловска и Соколовки с задержкой. Задержки рассчитаны по реальным расстояниям вдоль русла.
- **Модуль оценки риска:** уровень риска (низкий / средний / высокий) по 5 факторам с весами. В интерфейсе видно объяснение каждого фактора, прогноз уровня на 3 часа и время до опасного порога с диапазоном неопределённости. Алгоритм прозрачный, это не машинное обучение — именно он определяет официальное состояние и предупреждения.
- **QORGAN Sentinel (ветка `revolution/qorgan-sentinel`):** параллельная оценка обученной моделью **XGBoost** (учебная, на синтетических данных симулятора) — вероятность дойти до порога за 6 ч и блок «Почему такой риск?» с SHAP-факторами; **Telegram-бот** для операторов (привязка по коду, без спама); **звуковые сигналы** среднего и высокого риска ([docs/SENTINEL_ARCHITECTURE.md](docs/SENTINEL_ARCHITECTURE.md)).
- **Интерактивная карта и карточки станций:** графики, время последнего сообщения, факторы риска, история предупреждений.
- **Предупреждения:** создаются автоматически и не дублируются. Оператор отмечает их «просмотрено» и «обработано».
- **Роли:** гость, оператор и администратор. Администратор управляет станциями (CRUD), порогами и коэффициентами, пользователями (CRUD), видит состояние источников и журнал диагностики.
- **Прогноз по реке:** уровень у нижних станций рассчитывается по измерениям постов выше по течению — запас времени до опасного уровня до 119 ч, диапазон, самопроверка на истории против наивного прогноза и против тренда станции.
- Языки интерфейса: қазақша / русский / English. Вёрстка адаптирована от ноутбука до телефона.
- **Внешний датчик на Python через MQTT:** отдельная программа сама создаёт показания уровня воды и передаёт их через MQTT-брокер; QORGAN принимает их через тот же приём телеметрии, пересчитывает риск и создаёт предупреждения ([docs/PYTHON_SENSOR.md](docs/PYTHON_SENSOR.md)).
- Готов к публичному размещению: Docker + Caddy (HTTPS), строгий режим секретов ([docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)).

## Текущий статус
Готовы все обязательные функции ТЗ: вход по ролям, симулятор и приём телеметрии, модуль оценки риска, карта и карточки станций, **автоматические предупреждения с журналом**, **панель администратора**. Главное отличие — **«Прогноз по реке»**: сколько часов осталось каждому пункту до опасного уровня, с диапазоном и проверкой на истории ([docs/INNOVATION.md](docs/INNOVATION.md)). 305 автотестов на Node.js и 19 на Python (29.10, ветка eclipse). Перед системой — главная страница Hydro Future. Ход работ — [docs/PROGRESS.md](docs/PROGRESS.md).

## Запуск
Нужно: Windows 11, Node.js 24+, npm 11+. Команды выполняются в корне проекта (Git Bash или cmd).

1. Установить зависимости:
```bash
npm install
```
2. Создать файл настроек `.env` (один раз):
```bash
npm run setup
```
3. Запустить систему (backend и интерфейс одной командой; БД и демо-учётки создадутся сами):
```bash
npm run dev
```
4. Открыть в браузере **http://localhost:5173** — это интерфейс QORGAN.
5. Остановить: в окне CMD нажать **Ctrl+C** (при вопросе «Завершить выполнение пакетного файла?» ответить `Y`).

### Демонстрация одним щелчком (Windows): Python-датчик → MQTT → QORGAN
1. Двойной щелчок **`start-demo.bat`**. Он проверит Node.js и Python, при первом запуске сам установит зависимости (нужен интернет), затем откроет три окна — **QORGAN-server**, **QORGAN-broker**, **QORGAN-sensor** — и сайт http://localhost:3000/#/simulator. Уже запущенные части второй раз не запускаются.
2. На сайте войти оператором (логин и пароль — в `.env`: `SEED_OPERATOR_USERNAME` / `SEED_OPERATOR_PASSWORD`).
3. «Симулятор» → «Внешние датчики» → блок **«Подготовить чистое демо»** → «Начать новый чистый прогон» (если идёт старый прогон — сначала «Остановить прогон №…»; ничего не удаляется).
4. В окне **QORGAN-sensor**: буква + Enter — **D** опасный подъём, **F** спад, **N** норма, **Q** выход.
5. Завершить всё: **`stop-demo.bat`** (или закрыть три окна; в каждом также работает Ctrl+C → `Y`).

Можно и по отдельности: `start-qorgan.bat`, `start-broker.bat`, `start-sensor.bat` (`start-sensor.bat DANGER` — сразу в режиме опасного подъёма). Сценарий защиты — [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md), протокол и модель датчика — [docs/PYTHON_SENSOR.md](docs/PYTHON_SENSOR.md).

> BAT-файлы намеренно написаны только латиницей и с окончаниями строк CRLF: cmd.exe неверно читает UTF-8-кириллицу в .bat (раньше из-за этого окно сразу закрывалось с ошибками вида `'ова.' is not recognized`).

Для показа без режима разработки: `npm run build`, затем `npm start` и адрес **http://localhost:3000** (интерфейс и API с одного адреса). Не запускайте `npm run dev` и `npm start` одновременно — они работают с одной базой.

Демо-учётные записи — `operator` и `admin`, пароли указаны в `.env` (`SEED_*_PASSWORD`).

| Команда | Что делает |
|---|---|
| `npm test` | все автотесты |
| `npm run typecheck` | проверка типов |
| `npm run db:reset` | удалить БД и создать заново с начальными данными |
| `npm run db:backup` | резервная копия БД в `data/backups/` (время в имени — UTC) |
| `npm run db:fixture` | записать проверочные данные T2 (12 ч по 4 станциям) — отображаются как исторические |
| `npm run demo:wave` | консольная демонстрация паводковой волны (отдельная демо-база) |
| `npm run mqtt:broker` | локальный MQTT-брокер для Python-датчика (127.0.0.1:1883) |
| `npm run build` | собрать интерфейс в `apps/web/dist` |
| `npm start` | сервер на :3000 с собранным интерфейсом |

### Главная страница Hydro Future (ветка `revolution/qorgan-eclipse`)
По адресу http://localhost:3000/ первой открывается главная: Есиль в перспективе с потоком света по руслу, разделы
«Как работает», «Путь волны», «Настоящая система» и кнопки **«Открыть систему»** (главная панель, `#/dashboard`) и
**«Смотреть демонстрацию»** (настоящий «Демо за 2 минуты»; без входа — окно входа оператора, после входа демо
начинается само). Все цифры — с сервера, бейдж «Демо-данные · учебная модель» виден всегда. Если в Windows выключены
«Эффекты анимации», главная показывается статичной. Подробно — [docs/HYDRO_FUTURE_FINAL.md](docs/HYDRO_FUTURE_FINAL.md).

### Интерфейс QORGAN Eclipse (ветка `revolution/qorgan-eclipse`)
Главная панель построена вокруг карты: вверху — обстановка одной фразой и кнопка **«Демо за 2 минуты»**, ниже — крупная карта Есиля со станциями, затем **«Живая река»** — станции по течению, уровень относительно учебных порогов и куда движется угроза (это схема по данным станций, не модель затопления). Светлая и тёмная темы, KZ / RU / EN. Описание дизайна — [docs/ECLIPSE_DESIGN.md](docs/ECLIPSE_DESIGN.md).

### Как пользоваться интерфейсом (T4.1)
1. Нажмите **Войти** (справа вверху) → логин `operator`, пароль — значение `SEED_OPERATOR_PASSWORD` из файла `.env`.
2. **Главная панель** → крупная синяя кнопка **«Демо за 2 минуты»**. Запускается настоящий прогон «Быстрый паводок» (1 ч симуляции = 0,5 с). Панель демо показывает 5 шагов: нормальная ситуация → начало подъёма воды → рост опасности → волна идёт вниз по течению → объяснение и итог. Шаг меняется только тогда, когда это подтверждают данные сервера.
3. В демо: **Пауза / Продолжить**, **Завершить демо** (прогон останавливается, данные сохраняются), после окончания — **Повторить демо**. Если уже идёт другая симуляция, система спросит: показать её или остановить и начать демо.
4. Без демо: **Запустить паводок** (или **Начать заново**), **Пауза**, **Продолжить**, **Остановить** — на главной панели и в разделе **Симулятор**.
5. Справа на главной — **станции по течению** (сверху вниз) и карточка выбранной станции: уровень, оценка опасности, тенденция, короткое объяснение. Кнопка **«Подробнее»** открывает пороги, прогноз на 3 ч, факторы, качество данных и технические сведения.
6. **Симулятор**: выбор сценария карточками; повторяемость (seed), скорость, шаг +1 ч, создание прогона без запуска и сброс — в «Дополнительных настройках»; ручное вмешательство и история прогонов — в раскрывающихся разделах.
7. **Предупреждения** — журнал: «Требуют внимания» / «Активные» / «Все в прогоне», «Просмотрено», «Обработать» с комментарием, «История». **Прогноз по реке** — полосы по станциям, график с диапазоном, «Проверить на истории» (после прогона). **Администрирование** (вход `admin`) — станции и пороги, токены устройств, пользователи, коэффициенты модели, источники данных, аудит, резервная копия.
8. Шапка: переключатель языка **KZ | RU | EN** и темы (светлая / тёмная / как в системе). Кнопка со стрелкой внизу боковой панели сворачивает её до иконок; на телефоне меню открывается кнопкой ☰. Выбор языка, темы и панели запоминается в браузере.

### API оценки риска (T2)
`QRG-01` можно заменить на код или номер другой станции.

| Адрес | Кто может | Что показывает |
|---|---|---|
| http://localhost:3000/api/stations/QRG-01/risk | все | уровень риска, балл, главные причины |
| http://localhost:3000/api/stations/QRG-01/risk/explanation | все | вклад каждого фактора, качество данных |
| http://localhost:3000/api/stations/QRG-01/forecast | оператор, админ | прогноз на 3 ч, время до опасного порога |

### Проверка симулятора паводковой волны (T3) — одной командой
```bash
npm run demo:wave
```
Команда запускает сценарий «быстрый паводок» на **отдельной демо-базе** `data/demo-wave.db` (рабочая база не меняется), входит временным оператором со случайным паролем и печатает таблицу: виртуальное время (по Казахстану, UTC+5), уровень и риск 4 станций. Видно, как волна идёт Сергеевка → Явленка → Петропавловск → Соколовка; на середине — пауза 2 секунды, виртуальное время при этом стоит. Займёт около 20 секунд. Другие варианты: `npm run demo:wave -- GRADUAL_FLOOD`, `npm run demo:wave -- NORMAL`.

### API симулятора (T3)
| Адрес | Кто может | Что делает |
|---|---|---|
| http://localhost:3000/api/simulation/state | все | состояние: IDLE / CREATED / RUNNING / PAUSED / COMPLETED / STOPPED, виртуальное и реальное время, ускорение |
| http://localhost:3000/api/simulation/scenarios | все | сценарии NORMAL, GRADUAL_FLOOD, RAPID_FLOOD |
| http://localhost:3000/api/stations | все | станции, связи вдоль реки, задержки волны, датчики и пороги |
| http://localhost:3000/api/stations/QRG-01/measurements | все (24 ч) / оператор (всё) | история измерений |
| `POST /api/simulation/start`, `pause`, `resume`, `step`, `stop`, `reset`; `PATCH /api/simulation/speed`; `POST /api/simulation/interventions` | оператор | управление (кнопки появятся в интерфейсе T4) |

В каждом ответе о риске есть поле `context.mode`: `LIVE` — симуляция идёт, `PAUSED` — на паузе, `HISTORICAL` — данные прошлого прогона, `NO_DATA` — данных нет.

### QORGAN Sentinel: ML, Telegram, звук
- ML работает сразу: модель `ml/models/sentinel-model.json` лежит в репозитории, Python для показа не нужен. Переобучить: `npm run ml:setup` (один раз), `npm run ml:dataset`, `npm run ml:train`; тесты — `npm run ml:test`.
- Звук: значок 🔊 в шапке → включить, выбрать громкость, «Проверить». По умолчанию выключен.
- Telegram: токен от @BotFather — только в `.env` (`TELEGRAM_BOT_TOKEN`), затем «Предупреждения» → «Telegram-уведомления» → «Получить код». Без токена всё работает, бот просто выключен. Показ без интернета — `npm run telegram:mock` ([docs/SENTINEL_TELEGRAM.md](docs/SENTINEL_TELEGRAM.md)).
